# 可行性验证 — 2026-10-05（America/New_York）

**本机采集、分阶段模型判断和可追溯输出已经跑通。** 项目是高召回岗位信息池；实际申请由人或另一个 AI 处理。相关岗位不会因为经验偏高、学位、返校或入职时间而从信息池中删除，大公司使用 **★ LARGE** 标记，创业公司和 AI 公司继续保留。

## 采集和覆盖

配置已扩展到 **53 个来源：48 个雇主招聘源 + 5 个第三方来源**。本轮 52 个来源成功读取，累计 **13,365 条当前来源记录**；Arbeitnow 在分页过程中返回 429，未把不完整响应当作成功快照。这些数字是原始职位数，**不是 UXR 推荐数，也未全部完成模型判断**。跨平台的同一职位仍可能重复。

官方适配器包括 Greenhouse、Ashby、Lever、SmartRecruiters、Workday、Recruitee，以及 Google / Amazon 的招聘搜索。新增 Adobe、NVIDIA、ServiceNow、Ubisoft、Stripe、DoorDash、Coinbase、Spotify、Cohere 等。第三方包括 Remotive、Remote OK、Jobicy、Himalayas 和 Arbeitnow。各源范围、数量、间隔及限制见 [SOURCES.md](SOURCES.md) 和 [THIRD_PARTY_APIS.md](THIRD_PARTY_APIS.md)。Microsoft、Meta、Apple 等尚未覆盖，部分来源仅采集特定查询或近期窗口，不能声称覆盖整个市场或真正实时。

每条抓到的职位都进入本地模型判断队列，标题只决定处理顺序。当前公开文件是工作流程试跑的有限结果；README 明示待处理数量。未处理记录不会冒充经过模型判断的推荐。

## 匿名政策和经验层级

公开内容只保留通用研究能力及搜索偏好，不包含申请人的姓名、学校、履历、个人网站、联系方式或公民身份。目标包括 UX / 用户研究、设计研究、消费者与市场洞察、行为与社会研究、研究运营、产品与客户体验分析、人因、可用性、服务设计策略和项目评估。地点、雇佣形式及经验等级不构成硬性排除。

经验等级由招聘方明确的 **mandatory 最低年数**计算；preferred 年数单独输出。

| 等级 | 最低经验年数 |
|---|---|
| Junior | ≤3 年 |
| Mid | >3 且 <5 年 |
| Senior | ≥5 且 <8 年 |
| Staff | ≥8 年 |
| Unknown | 未明确说明 |

职位标题里的 seniority 单列，和数字冲突时标记供下游复核。实习不自动等于 0 年；无数字不根据标题猜测。原文证据与结构化冲突标记仍随结果提供。

## 分阶段推理与重试

第一阶段判断研究相关性并提供一段原文证据；相关或不确定的职位进入第二阶段，提取经验、工作形式、资格要求及证据。第一阶段结果只是可修正的线索，第二阶段继续读取原始岗位文本。

每阶段默认最多立即尝试 3 次；校验失败把安全的错误反馈放回 prompt，调整输出预算与采样温度。持续失败进入 SQLite 重试队列，30 秒起指数退避、最高 6 小时；后续循环重新处理。已完成的第一阶段保留，进程重启可恢复，不必重新做全部工作。失败记录只公开来源事实和待重试状态，不展示未通过验证的模型字段。

旧版本曾失败的 Roblox、Lyft 两条真实职位，在匿名分阶段版本中均通过重新入队完成，其中 Roblox 经历 5 次请求、Lyft 2 次请求。新版经验政策又单独进行真实职位试跑，记录见 [benchmark-summary.json](benchmark-summary.json)。这种实测证明请求流程和校验能运行，**不代表重试必然成功，也不等同于语义准确率或召回率**。

## 本机模型对照

硬件 Apple **M5 Max / 128GB**；macOS **27.2 / 26B5091g**；Xcode **27.0 / 27A266a**。独立 uv 环境使用 MLX 0.32.3、mlx-lm 0.31.3、Transformers 5.18.0。两个模型均为机器已有的 8-bit 权重，未下载新模型；Qwen3.8-27B 权重约 27.48 GiB。

早期单阶段版本用同一组 **15 个案例（9 个合成边界 + 6 个真实职位）**对照，温度 0、关闭 thinking、最大 900 输出 token、顺序推理。它不是随机抽样或当前分阶段版本的独立评测。

| 指标 | Qwen3.8-27B-8bit | Qwen3-8B-8bit |
|---|---:|---:|
| 原始判断符合案例期望 | 14/15 | 13/15 |
| 结构、原文引用及字段一致性通过 | 15/15 | 6/15 |
| 判断符合期望且通过全部校验 | 14/15 | 6/15 |
| 单条耗时中位数 | 17.53 秒 | 4.99 秒 |
| 解码速度中位数 | 15.82 token/s | 53.50 token/s |
| MLX 峰值内存（十进制 GB） | 31.57 | 9.68 |

27B 在这台机器上可运行，作为证据提取基线比本次测试的 8B 稳定。**仅比较了这两个模型，不能断言是本机最佳选择。** 8B 的主要失败是引用和字段一致性；对更短的第一阶段任务仍值得另测。当前并未部署大小模型混合路由。

来源：[Qwen3.8-27B 模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)、[MLX LM](https://github.com/ml-explore/mlx-lm)。保留的旧指标不包含申请人资料，不可当成当前版本质量指标。

## 链接与输出边界

模型 schema 不接收链接；标题、公司、地点、ID、来源页来自采集接口。链接检查要求页面可达、符合职位身份且来源与页面校验均在 24 小时内。已关岗、重定向回招聘首页、阻止访问或身份不明确的页面不会标为已验证。Recruitee 的部分不含 ID 的 URL 会保守保留为未验证。

官方记录的 `employer_verified` 和第三方记录的 `verification_scope=aggregator_listing` 明确区分。第三方来源页可达并不证明雇主还在招聘；没有明确雇主投递地址时 `application_url` 为空，不能凭空生成。第三方署名及回链随每条记录保留。滚动 feed 里暂时消失的记录不会直接当成关岗，但最近观测过期后也不再视为已验证。

抽查发现自由文本备注会把优先学历写成必需学历，或添加来源未说明的工作许可限制。因此公开序列化不再转述模型的自由文本理由、备注和疑点；这些原始输出仅保存在本地。公开的空备注数组不代表没有资格条件，短原文引文也不是完整资格清单。Amazon 的基本／优先条件分节已在采集端保留，修正缓存不改变原抓取时间。

结构校验、逐字引文、经验数字检查及必需/偏好分离降低错误，**不证明所有语义判断正确或链接今后仍有效**。下游投递前需要再次打开雇主页面。公共 JSONL 的使用约定见 [HANDOFF.md](HANDOFF.md)。

## 成本和运行边界

这些已接入的公共接口没有购买 API 套餐或设置付费密钥；仍有更新延迟、署名、限流及使用条件。免费不代表无限制或永久免费。本地推理没有逐 token API 账单，仍占用电力、内存及 GPU 时间。

13,365 条记录需要先做第一阶段，相关职位再做第二阶段，失败还会重试。不能把旧单阶段中位耗时直接当成当前全量用时；初始队列需要持续消化，随后只重新判断新增、内容变化或政策/模型改变的记录。当前尚未完成全量推理和长时间稳定性验收。

已验证本地 `/v1/chat/completions`，可配置共享 backend；权重位于统一模型缓存。未修改游戏项目或验证两者并发时延。独立 uv 环境绕开旧 conda 环境的 libomp 冲突，未修改 conda 或使用 KMP_DUPLICATE_LIB_OK。

提供前台 `watch`、持久化状态、源级最小采集间隔、失败退避和进程锁。**尚未安装登录常驻、启用自动 Git push 或发送通知；Mac 睡眠时不会工作。** 初次公开发布是经过匿名审计的快照；持续更新需要运行 [SETUP.md](SETUP.md) 中的命令，并在每次发布前执行隐私审计。
